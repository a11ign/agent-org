# agent-org: working in this repository

The commands, run from the repository root:

- **Install:** `pnpm install`. The lockfile is `pnpm-lock.yaml`; pnpm is the version `release.yml` pins (10.34.5).
- **While you work: `npm run check:changed`.** One cached check of your change, against the merge base with `origin/main` (committed, staged, unstaged and untracked changes together). It prints what it ran and why. Run it after each edit and before you push, and run the full `npm test` and `npm run lint` only when it says FALLBACK (it then runs the whole suite and the whole lint itself). `-- --plan` prints the plan and runs nothing; `-- --base <ref>` names another base. It does three things:
  - **Lint** (`scripts/lint-cache.ts`): ESLint with `--cache` on the changed files. The cache is in `node_modules/.cache/eslint/<key>`, and the key is a hash of `eslint.config.ts`, `pnpm-lock.yaml` and the installed version of every ESLint package, so changing any of them drops it. `npm run lint` uses the same cache over the whole tree.
  - **Typecheck:** `npm run typecheck`, the whole program (a type error is in the file that uses the one you changed), incrementally: its build info is in `node_modules/.cache/tsc`.
  - **Tests** (`scripts/rstest/select-tests.ts`, `import-graph.ts`): every test file that imports a changed file directly or through any number of files, names a changed file's path or a relative path to it in a string (`new URL("./x.ts", import.meta.url)`), or is itself changed; never tests picked by name. A source, test, unit or script file that is added, changed or deleted also selects the tests that read the whole tree (they list a directory, or use a tree-walking helper directly), because no import leads from the file they forbid to them. It always runs the suite against the same fixture project CI makes, and ignores the `AGENT_ORG_HOST` of your environment (a worker's names the live project, and a suite run against that is not CI's). A change to a shared fixture, `scripts/rstest/*`, the runner's setup files, `package.json`, the lockfile, a config, `.github/` or a data file no test names FALLS BACK to the whole suite and the whole lint. A test that builds a path from parts, or an import built at run time, is not seen by the graph: CI runs every suite on every push and remains the gate.
- **Test:** `npm test`. The suite runs only where its files exist: CI's `suite` job copies the fixture project to a temporary directory and runs rstest with `AGENT_ORG_HOST` naming that copy's host declaration (`.github/workflows/ci.yml`). From a bare checkout `npm test` refuses and prints the narrow form: rstest on the changed test files, with `AGENT_ORG_HOST` set to a host declaration.
- **Typecheck:** `npm run typecheck`.
- **Lint:** `npm run lint`. ESLint with `@george2f/eslint-plugin-clean-code` over `src/`, `scripts/`, `plugins/` and `ui/` (`.ts`, `.tsx` and `.astro`), configured in `eslint.config.ts`.
- **The UI** (`ui/`, a private package of its own with its own lockfile, not a workspace member): `pnpm --dir ui install` once, then `pnpm ui:dev`, `pnpm ui:build`, `pnpm ui:typecheck` and `pnpm ui:test` from the root. `ui:test` needs the build and Chromium (`pnpm --dir ui exec playwright-core install chromium`). The README's section "The board UI package" says how it works.

Fix every lint error before you push. A rule that is still at `warn` in `eslint.config.ts` has its own follow-up ticket, which fixes its warnings one rule at a time, so leave those warnings alone unless your ticket is that one. A warning does not fail `npm run lint`.
