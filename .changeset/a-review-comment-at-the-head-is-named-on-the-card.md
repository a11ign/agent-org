A repository whose review runs as a CI workflow that posts a comment, not a review, no longer reads on the card as if nothing reviewed the head. The host file's new `tickets.reviewComments` names such comments by their author and the text their body starts with (`[{ "author": "ci-bot", "startsWith": "Review finished" }]`). Where no review is at a pull request's head and the newest matching comment was posted, or last edited, after the head arrived, the card reads `review comment by ci-bot at <head>, awaiting approval` where it read `review: none yet at <head>`. Only the words change. The comment is never an approval: the run stays Awaiting review, the arm bot is not asked to arm it, and readiness and merging still wait on an approving review. Code host contract 4.1 adds the optional `PullFeedback.commentReviewAtHead` and an optional fourth argument to `readPullFeedback`. The GitHub plugin reads it in the query it already makes and adds no GitHub call. It takes the head's arrival as the later of the head commit's time and a force-push to it, because GitHub gives no time for an ordinary push. Absent or empty, the setting changes nothing.
