A queued ticket that overlaps a run in its repository starts at once, stacked on that run's branch, and no longer runs beside it off `main` (A11-374). What a ticket with no plan claims is, in order: the files of its open pull requests, the paths its ticket's `## Region` names, else its whole repository, so a ticket queued without a plan is no longer treated as overlapping nothing; a run at work with no files known holds its whole repository. The run it overlaps must have an open pull request or a pushed branch to build on (the board reads the branch of a run at work beside the pass); until then the ticket waits, saying "Waits for <KEY> to push its branch". A ticket that overlaps two open stacks stacks on the one most recently updated, and its brief names the other's branch. The card says why it is stacked ("overlaps `<file>`", or "same repository, files not known"), and A11-248's restack, the arm bot's stack merge and A11-370's CI, notes and start priority apply to it as to a blocker. A conflict round no longer counts toward the board's round cap: only rounds that answer a review do. A conflict round counts toward it only when the pull request's base has not moved since its last conflict round, which is the worker's own failure to resolve it. Every conflict round's reason starts "Conflict <n> on #<pr>:", and from the 4th conflict on one pull request its feedback names the pull requests it keeps colliding with. `ticket:serve` and its pool are the only consumers; the queue file gains `regionPaths`, `overlapStack`, `pushed`, `conflictRounds` and `conflictBase`.
