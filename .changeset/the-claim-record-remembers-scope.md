The claim record remembers the scope the row was claimed with (a11ign/a11ign#4739, the first of three rows split from #4627, class `row-not-finishable`: scope added to a row after it is claimed is a new row, never folded into the claimed one). `claimRecordComment` takes a `scope` and writes a `Claimed-scope: <hash>` line; `claimRecordFrom` returns it as `scope: string | null`, `null` for no record, for a release and for every claim written before the line existed, so no existing reading changes. The new pure `scopeHash(body)` is a 12-character SHA-256 prefix over the row's `## Region` and `## Acceptance` sections only, whitespace-normalised and read by the same `extractLabeledSection` the template-fields check uses; prose elsewhere in the row gives the same hash, and a widening, a narrowing or an edited Acceptance each give another. The claim passes the hash of the body it had just read for that check, from the declared tracker's repository for a keyed row, and leaves the line out when that body could not be read, because a hash of nothing would read as "the scope was empty". The comparison against the live row is a later row (a11ign/a11ign#4759).
