A run that used up the board's three rounds (`MAX_FEEDBACK_ROUNDS`) no longer reads Needs you (A11-343). A round cap is not on the escalation list, so a watched run at its cap goes to the PLANNER, as a stand-off does: a review round that starts as the planner, with the rounds so far, the feedback that reached the cap, the ticket's Decisions and the open blockers. The planner writes `cap-decision.json` and ends `reviewed`: `{ "decision": "round", "reason": "..." }` records a Decision (an amended plan is attached when it wrote one) and the board starts one more round of the worker with it, which counts toward no cap; `{ "decision": "waiting", "ticket": "A11-341", "reason": "..." }` marks the run as waiting on that ticket, which reads "Waiting on A11-341" on the board (status Waiting), holds the run's feedback rounds, and starts a round again on the next tracker sweep after that ticket's pull request merged or the tracker completed or canceled it. Only a `needs-human` outcome that names an item of the escalation list reaches a person. The Stop hook refuses the planner's `reviewed` until `cap-decision.json` is usable. A re-review that finds a watched run at its cap goes the same way. A machine with no planner, and a run the board does not watch (one parked on a question), are handed to a person as before. A round that answers only checks which count toward no cap (a check a line of the ticket's Decisions calls unrelated, or one a rerun for a worker's "not mine" found red again, kept as `redAgain` on the pull request's record from head to head) no longer counts toward the cap.
