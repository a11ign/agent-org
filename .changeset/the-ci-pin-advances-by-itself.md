`PROJECT_REF` in this repository's CI advances by itself, and a pull request red only on pin drift waits for it instead of stopping a worker (a11ign/a11ign#5151). `project-ref-bump.yml` runs hourly (and on dispatch): when a11ign/a11ign `main` has a commit past the pin whose `gate` check is green, it keeps ONE pull request on `bot/project-ref-bump`, main plus the one `PROJECT_REF` line, and arms it with an Octo STS token (`project-ref-bump.sts.yaml`; a `GITHUB_TOKEN` push would fire no `gate`). Its `refresh` job, on a push to `main` that moved the pin, updates the branch of each same-repository pull request whose newest `ci` run is red on `copies-drifted`, because a re-run keeps the old merge commit. The whole workflow is OFF unless the repository variable `CI_AUTO_BUMP_PROJECT_REF` is `true`. `ci-failure-class.ts` gains the class `waiting-on-pin-bump` and the route `wait-for-pin-bump`: the fact is READ true only when the one non-roll-up red check's log names `copies-drifted@…`, every named copy cites a commit the head's pin lacks, and the OPEN bump pull request's pin reaches it; the provider is not offered the class without the fact. `wake.ts` tells the holder to wait on that route even with no provider; every other order is byte-identical.
