When a ticket run's worker hits the Claude allowance, the board starts no other ticket run until the reset Claude Code named, and once the reset has passed it tells each run parked on the allowance to carry on, without a person (A11-434, step 2 of 2). The allowance counts as back 2 minutes after the named reset, so a run isn't refused again at the reset itself. A run sitting on Claude Code's limit menu has the menu cancelled first. A run that doesn't take the prompt is told again after 15 minutes, not on every pass. The hold on starts is kept in the queue file, so it survives a restart. It lapses on its own after the reset, and it ends early when a held run answers again, for example after a person switches it to usage credits. A board restart no longer sends its resume prompt to a run held on the allowance. A talk session, and a new-ticket request a person makes in the form, still start. An after-merge check run waits, as it does while the queue is paused.
