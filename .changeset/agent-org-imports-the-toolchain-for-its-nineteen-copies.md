The tool carries seven of the product's libraries as declared copies, not nineteen: 12 of the 19 `// COPIED FROM` files in `src/lib` are gone and every importer of those takes the same names from `@a11ign/toolchain/lib/<stem>` at the version `package.json` declares (`^0.7.0`; a11ign/a11ign#4425, phase 3, row 5 of 5). Seven stay, for two separate reasons. Six are in the import closure of `work-gate.ts`, `work-tick.ts` and `wake.ts` (`changed-files`, `cli-flags`, `git-env`, `local-import-closure`, `npm-cli-executable`, `worktree-resolution`): that closure runs from the host's installed checkout before any install, and `a11ign/a11ign#2174` requires it to load with no `node_modules` (ruled by ceo on a11ign/agent-org#522; a11ign/agent-org#715 is the parity test for them). The seventh, `walk-scope.ts`, stays because the toolchain's `REPO_ROOT` is its own install directory and not the project (a11ign/a11ign#4718); it imports its two helpers from the toolchain, as the product's own copy does. A project that installs the tool should read what moves with that before taking this release:

- `@a11ign/toolchain` is a `dependency`, not a `devDependency`: the commands, `pr:open` and the rest import it at run time, so an install that leaves it out stops at the first import of one of the twelve. The gate, the tick and `wake` do not: their closure imports nothing from it. Anything that runs the tool from an installed checkout needs `@a11ign/toolchain@^0.7.0` in that install before it takes this version.
- `agent-org changed-packages`, `ci-changed`, `isolation-gate` and `test-memory-cap` are removed from the command table, because each ran the main guard of a `src/lib` file that is no longer here. The same programs are `@a11ign/toolchain/lib/<name>`; `git grep` over a11ign at `98722a1fe` finds no script, workflow or `package.json` entry that names them. `changed-files` stays: its copy does.
- `src/lib/tree-wide-guard.ts` stays, as a re-export of the toolchain's, because `agent-org/tree-wide-guard` is a declared export the product resolves (`packages/guards/src/tree-wide-guards.ts`); it goes when the product stops resolving it.
- The `copies-drifted` org-health signal stays and compares the seven pairs left. It reads `unknown` for two of them (`local-import-closure.ts` and `worktree-resolution.ts`: their originals are no longer at the header's `packages/guards/src/` path), the same line the signal printed for eleven pairs from 2026-10-10T16:14Z; it is shorter, not gone.
