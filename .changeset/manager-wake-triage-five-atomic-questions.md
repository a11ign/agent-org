Manager-wake triage asks five atomic yes/no questions over structured order fields and composes the route in code, where #4385 asked one broad `wake|digest|drop` question (69% of its answers sat under the 0.7 floor). The provider sees only `cause`, `causeKey`, `session`, the minutes since the same causeKey was last delivered to the same seat, whether main is red, and whether a chairman direction is attached; never the order text. Questions: asks something only this seat can answer; repeat of something delivered in the last hour; names a red main; names a chairman direction; informational only. Code composes: a red main or a chairman direction always wakes (and, when the state already says so, asks nothing); a repeat inside the hour, or informational-only that asks nothing of this seat, is digested; otherwise it wakes. No provider, no key, `wake-triage` switched off, a refusal, a timeout, or an under-floor answer takes the question's own fallback, which wakes, so the deterministic behaviour is every order wakes. `"provider": "none"` still returns the orders untouched and writes nothing, byte for byte. A held order that is offered to the same seat again within 24 h of its delivery gets one `outcome` line, `needed-action: true`, labelled a PROXY. a11ign/a11ign#4631.
