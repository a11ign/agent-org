A red `cross-repo` leg, or a red nightly, of a declared code repository's `ci.yml` on `main` now wakes the fixer. `trunk-red.ts` asked for `event=push` runs and read the run's conclusion and the `gate` job, and a `continue-on-error` leg leaves both `success` while its own job reads `failure` (measured on lab's `main`, 2026-10-10: `checks (cross-repo)` was `failure` on all 11 newest push and schedule runs, and every one of them read `success`). `readTrunkRed` now also reads `event=schedule` runs of a declared code repository, takes the newest verdict run of either event, and reads its jobs even when it is green; a red `cross-repo` job of a green run is red `main`, and the order names the leg, says `gate` read green and sends a nightly's red to `product-manager` rather than to the merger of the newest commit. A refused runs read refuses the whole read, so a nightly is never reported red without the push after it. The primary's `trunk.yml` is read with the same calls in the same order, and a repository with no `cross-repo` job gets the same answer, at the price of one more `jobs` read on a healthy tick (three REST calls per declared code repository instead of one). a11ign/agent-org#539.
