`agent-org onboard` reads like a setup wizard. In every list, Space ticks and unticks the highlighted item and Enter confirms, the filtered list included (typing filters, and a space is never typed into the filter), and the list's last line says so: `↑↓ move · space select · enter confirm · type to filter`. The Linear key step is "Connect to Linear": it says the key is kept in the macOS Keychain (a private file on Linux), where to create one (Linear → Settings → Security & access → Personal API keys, with Read and Write access), asks for it at a prompt that does not echo, checks it against Linear at once and says whose account it is, and asks again for a key Linear refuses; where the key is kept is no longer asked (`--linear-keychain` and `--linear-key-file` still name another place), and the Keychain takes the key on `security -i`'s standard input instead of an argument. The clone confirmation lists the repositories by name with the path each goes to, each clone prints one ✓ or ✗ line when it ends, and the summary table is printed once. Each plugin is one ✓ or ✗ line in the setup words of its manifest's new optional `agentOrg.setUp` (`Linear connected as the tracker`, `GitHub connected as the code host`, `Board served on this machine`), a step may add a `summary` line of its own (`StepResult.summary`, an additive field of every contract), and onboard ends with `agent-org is set up on this machine.` or `agent-org is not fully set up: N steps above need fixing.` and the commands to run next. The internal wording, the clone commands, each service and doctor's whole report show with the new `agent-org onboard --verbose`. The exit status is unchanged.
