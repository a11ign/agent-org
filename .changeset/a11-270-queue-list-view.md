The queue the board's pages poll every 5 s is a list of what they draw (A11-270, step 4 of 4). `GET /api/queue` sends each run with the fields the Runs and Tickets pages and the board-view code they run read, its ticket's key, title and address, and no log; a run that holds and contests no path (it ended, and so did its ticket) sends none of the files it once held, and `learned` and a blocker's `blockersDeclared` are sent only where the page reads them. On a queue shaped like the agents host's, 1.3 MB of JSON becomes 0.34 MB, and 15 KB on the wire. A new `GET /api/queue/<key>` answers one run in full with its log, 404 for a ticket the queue holds no run of: a run's page draws from the list at once and reads its steps and its timeline from there, in place. The instance gzips an answer of 4 KB or more for a client that takes gzip, and the page's service asks for it, so an SSH tunnel carries the packed bytes; an instance from before sends text as it did, and one from before this release is read as it was. The page-timing script gains a Run page and exports its page list, and `page-timing.test.ts` keeps the 1 s first-load budget over a fake SSH tunnel in CI.
