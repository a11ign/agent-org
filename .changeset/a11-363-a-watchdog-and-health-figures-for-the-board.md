The board restarts itself when it stalls, and shows why. `GET /api/health` serves rolling figures: event-loop lag p50 and p99 over a minute and an hour, synchronous holds an hour, Linear and GitHub call failures per 100, the time since a run started, the startable queued runs and free slots, and the time since a `fill()` pass completed with the reason the latest one returned early. The new `watchdog` service (`agent-org ticket:watchdog`, every minute, outside the board's loop; `agent-org update` registers it) restarts the instance when startable runs and free slots have seen no start for 10 minutes, when no `fill()` pass has completed for 5 minutes, or when `/api/health` does not answer within 30 s. It logs and counts each restart (`tickets/watchdog.json`), waits while a run is still starting, and leaves a stopped instance alone; more than 2 restarts in an hour make the board ask for one defect ticket for the hour. A stopping instance starts nothing more and waits up to 15 s for runs whose agents are not open yet, so a restart keeps running runs running. Doctor and the board's sidebar show the figures and flag a loop p99 over 100 ms, call failures over 1%, and any watchdog restart in the last day (A11-363).
