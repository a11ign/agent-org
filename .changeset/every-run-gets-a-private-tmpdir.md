Every ticket-mode run now starts with a private `TMPDIR`, `<base>/run-t-<run id>` (`src/ticket-mode/run-isolation.ts`; `<base>` is `A11Y_PRIVATE_TMP_BASE`, else `~/.cache/a11ign/tmp`), so whatever a worker's tests and tools write with `os.tmpdir()` stops piling up in the shared `/tmp` (about 19,600 entries when the agents host panicked on 2026-10-25). `runEnvOf` builds it with the ticket's variables, so a run started again after a restart (A11-279 step 2) gets the same directory, and a run started before this change, which has the ticket's variables and no `TMPDIR`, is not started again for that. The directory is made when the run starts (a failure to make it starts the run on the shared `/tmp` and says so). On every tick the board touches (and makes again, if the user tmpfiles rule or a cleaner removed it) the directory of each run that is live or holds a workspace, so no other janitor finds a quiet run's directory old, and removes the directory of a run that is neither, one entry per call and at most 500 entries a pass, and not one modified in the last 10 minutes; a symlink named like a run directory is removed as itself. A run queued again for a review round starts in a new, empty directory: the earlier one went with the run's workspace. The instance passes `privateTmpBase`; a pool built without it (every test) gives runs none. A11-279.
