The org side runs a project's tree-wide guards on an agent pull request, and the result gates arming (a11ign/agent-org#1503, receiving side of a11ign#5460, ADR 0045 cut c). A guard is a tracked `*.test.ts` that imports the `declareTreeWideGuard` marker and calls it (comment-stripped, the same reading a11ign's `guardSweep` discovery makes); `treeWideGuardFilesIn(cwd)` finds them in a merge checkout and `runTreeWideGuards` runs them under the project's own runner (`pnpm exec rstest run --config scripts/rstest/rstest.config.ts`, read off its `VERDICT` line; plain `node --test` where the project has no such config) with tokens and secrets scrubbed from the environment. `treeWideGuardVerdict` is `pass`/`fail`/`not-run` and never a pass on doubt: no files found (the sweep's floor of 1), a run that ran nothing, fewer files than asked, an unreadable verdict, a timeout or an unprepared checkout are all `not-run`. `firstRefusalOf` combines this with the acceptance verdict so one arming is gated by both. The tick runs it only when `A11IGN_PR_TREE_WIDE_GUARDS_BY_GATE=on`; the default is off, so merging this changes no live behaviour. The new code is in `src/lib/tree-wide-guard-org-side.ts` because `work-gate/tick.ts` must load with no `node_modules`; `./tree-wide-guard` (the marker) is unchanged and still exported for pinned a11ign tool versions.
