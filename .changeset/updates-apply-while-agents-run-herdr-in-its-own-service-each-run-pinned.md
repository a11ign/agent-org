Updates apply within minutes while agents run (A11-169). herdr, which holds every worker's pane, runs in a service of its own (`agent-org-herdr.service`, launchd `io.github.agent-org.herdr`) that the instance and the terminal `Want=` but nothing restarts with them; `agent-org start herdr --move`, run once at a quiet moment, moves a server that runs outside it and retires the `KillMode` drop-in and the gh-wrapper watchdog, and `doctor`'s `herdr scope` passes only for a server in the unit. Each release installs into its own folder, `<agent-org home>/tool/versions/<tag>`, built from a bare mirror, and `tool/current` names the newest; `install.sh` makes this layout, and the first `agent-org update` from a checkout install rewrites the units, the launcher and the host file's `tool` once. A run's hooks and commands name the folder it started on, recorded at each start and round, so an update leaves live runs on their version (`doctor` lists each run's), and folders are pruned once no live or parked run names them. The auto-update timer runs every ten minutes and the deferral is gone. A release whose changeset's first line starts `Breaking: ` drains instead: no new run starts, the Board says so, and after `tickets.updateMaxDeferHours` the live runs are stopped and re-queued onto the new version. The conventions plugin's refresh no longer waits for a quiet moment (`plugins-deferred.json` and the `plugin refresh` row are gone); `doctor` fails a `plugin copy` row when a refresh rewrote a folder a live run uses.
