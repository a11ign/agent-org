A merge-queue entry that stands `AWAITING_CHECKS` for more than ten minutes (`QUEUE_ENTRY_NO_RUN_MINUTES`) with no `merge_group` run on its group's head commit is named by the gate, dequeued and armed again ONCE with no model turn, commented on the pull request (`queue-entry-no-run: <sha>`), and counted per day (a11ign/agent-org#1195; a11ign#928 sat 50 minutes on an entry whose CI never started). It is behind the machinery flag `queue.queueEntryNoRun`, which ships OFF and is switched by `machinery:flag`; with it OFF the cause reads and writes nothing. A run list that could not be read is "unread", never "no run". The act is taken on the tick after the entry is first seen, and the once is keyed on the pull request (a re-queue builds a new group sha) and written before the dequeue. A repeat on the same pull request is not re-queued: it is raised as the `queue-entry-no-run` org-health signal, with `queue-head-age` carrying the position-1 entry's age; both are `digest` classes. The entries read, the runs-by-sha read and the `dequeuePullRequest` mutation are argument builders in `src/ticket-port/queue-entry-reads.ts`, so `docs/gh-call-baseline.json` is unchanged. The dequeue was not run against a live entry and whether it clears auto-merge is not known.
