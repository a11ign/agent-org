A `spec` block can be linted (a11ign/a11ign#5117, the Haiku push). `src/spec-lint.ts` reads the block of a build row and refuses, naming the FIELD: a listed file that does not exist and is not `new: true` (`files[2]`), a test case whose `then` names no value (`tests.cases[0].then`), a `run:` that does not parse, names a program not on PATH or never names the tests, "TBD" / "etc." / "as appropriate" / "handle edge cases" without a list, more than six files or more than one subsystem, and an empty `out_of_scope`. What could not be asked (no checkout of a repository, no shell) is reported as `unchecked` and never refuses. Jev's spec-review verdict is a WARNING: below 3 of 5 it carries the `spec:review` label and wakes `product-manager`; a fallback, no provider or an unreadable answer warns nobody, and nothing blocks. The daily retro counts the `Underspecified: <field>` stops by field from one paginated comment list per tracker (`src/ticket-port/comments-since.ts`) and prints "Underspecified stops by field", with a line asking for a `ready` class row for any field above 2 a day. Behind `rows.specLint` in `.agent-org/project.json`, absent meaning OFF; revert is the flag off. This release does not yet WIRE the lint into promotion: `row-file.ts` still promotes as before until the follow-up row lands.
