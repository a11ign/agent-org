The **publisher** and the **reviewer** are now bundled **agent-org plugins**: `plugins/slack` (the publisher, contract 1.1) and `plugins/atomic-reviewer` (the reviewer, contract 1.0, named `atomic` through the new optional `agentOrg.name` of a plugin's manifest, so no live host file changes). No concern's code is built into core any more: the built-in rows and the pin that kept core on them (`CORE_RUNS`) are gone, and "none" is the absence of an enabled plugin. `agent-org plugin list|install|enable|disable|uninstall|config` and the Settings page's Plugins section manage both with no core change. The Slack plugin brings the settings `run`, `model`, `effort` and `connectors` (their schema entries moved into its manifest), the `post-pr-to-slack` skill (the hook reads it from the manifest, as data, and refuses it to every run but a publish run), two doctor rows (the run names `{prs}` and `{dir}`; the connectors are a non-empty list anchored at `^mcp__`) and an onboard step that asks for the run and the connectors. The publisher contract goes to 1.1: `agent()` names the publish run's model and effort, which the plugin owns. The atomic reviewer plugin brings the gate's codex reviewer (its port, seats, claims and verdict files moved out of `src/ticket-mode/reviewer-port.ts`; the gate itself stays core's and reaches the plugin through `deps.reviewing`), the doctor rows `reviewer gate` and `codex`, and an onboard step that says what is left of Codex. `ticket:review` starts the enabled reviewer, and refuses by name, with the enable or install command, when there is none.

**Reviews required** is a per-machine setting of the reviewer concern, `tickets.providers.reviewer.required`, valid under any provider (`none` included). Absent, it is true when the block (or the old `tickets.reviewer`) names a reviewer plugin, enabled or not, and false when it names none or there is no block: the machine that runs the atomic reviewer requires it, and the one where people review does not. Required and the reviewer off (none, switched off, or one whose gate does not load): the Board shows the banner "Reviews are required and the reviewer is off", each open pull request's line says "waiting on the reviewer (off)", and `agent-org doctor` fails with `agent-org plugin enable atomic` (or `install`). Not required and no reviewer: each run's open pull requests say "awaiting your review", and nothing else is shown. Disabling the reviewer stops new starts only (a reviewer still running finishes and posts); enabling it resumes on the next board start, with a reviewer on the current head of every open pull request, once per head. A publisher that is installed and disabled hides the Publish buttons and says "publishing off" on each run Ready to merge; enabling it publishes nothing retroactively. `plugin config atomic required=false` sets the key; uninstalling the reviewer keeps an explicit one.
