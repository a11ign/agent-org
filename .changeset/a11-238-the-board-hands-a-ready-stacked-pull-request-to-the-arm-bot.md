An approved stacked pull request with its required checks green now reaches the merge queue with no person, even when it turned ready after its approval. GitHub refuses auto-merge for a pull request in a stack, so the arm bot merges the bottom open member of a stack with GitHub's stack merge (the previous release); the board now hands such a pull request back to the arm bot, once per head (and again after 15 minutes if it is still open), whenever its checks go green or its head moves after a member below it merged. The board never merges: it dispatches the arm bot's `arm-approved` job, which re-reads everything with its own token. When GitHub refuses the stack merge, the run's card shows GitHub's reason (`GitHub refused the stack merge of <pull request>: <reason>`) until the pull request's head moves, and then the board asks again; if the arm bot cannot be dispatched, the card says `The board could not hand <pull request> to the arm bot: <reason>` and the next sweep tries again. A pull request that is not in a stack is left to auto-merge, as before. The worker brief for a stacked step says no person is needed to merge it, and that a stack is never unstacked. The code host contract is 1.16: `stackMergeFactsOf` and `requestStackMerge` are optional, and a code host of 1.15 is read as one that asks the arm bot for nothing.
