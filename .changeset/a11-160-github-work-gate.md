The work gate no longer calls GitHub from core: the 19 files of `src/work-gate/` that held a `gh` argument list, a parse of GitHub's answer or the spawn of `gh` ask the code host's `rows` (contract 1.9) for what they need, by name (`labeledEventTimesOf`, `newestLabellerOf`, `commentActivityOf`, `rowTimelineOf`, `waitRefOf`, `pullsOfBranch`, `newestMergedPulls`, `commitShasOf`, `compareDiffOf`, `failingCheckNamesAt`, `mergeGroupRunsOf`, `readRequiredContexts`, `closedClaimedRowsOf`, `closedRowsCarryingLabels`, `commentOnRow`, `addLabelToRow`, `markPullReady`, `addRowToProject`, and the rest), implemented in `plugins/github/rows/gate-*.ts`. Each builds the argument list the gate built, so the tick's memo, budget and call census see the same calls; the decisions stay in core. The process the gate's executor starts is the plugin's: `ghWithin` keeps the bound and the line it tells over `rows.gateRun`, and `runBatch` keeps the memo, the budget and the chunking over `rows.runTogether`. `docs/gh-call-baseline.json` goes down by the gate's 19 files. The gate arms an ejected pull request with `armPullAuto`, whose `gh` arguments are in another order (`pr merge --auto --merge <n> --repo <r>`). The fake code host's world gained `gate` (a row's label history, the tracker's events, checks, runs, diffs, tags) and a comment's `author`. The plugin's `deps.exec` takes `killSignal` and `maxBuffer` and answers `signal` and `spawnError`, so a cut `gh` is killed with SIGKILL and fails as `execFileSync` failed it.
