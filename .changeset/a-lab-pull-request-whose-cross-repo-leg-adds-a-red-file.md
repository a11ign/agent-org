A lab pull request whose `checks (cross-repo)` leg fails on a test file the newest trunk run passed is not armed unless its body declares `Cross-repo-red: <row>` naming an OPEN row (a11ign/agent-org#992, class `main-red`). The leg is `continue-on-error`, so `gate` read green and such a pull request merged and put `main` red, which `readTrunkRed` then read AFTER the merge (lab#81 on 2026-10-11). `src/cross-repo-red.ts` adds `failingFilesFromRstestLog` (the lab leg runs rstest, whose failed log has ` FAIL  <file> > <name>` lines that `failingTestsFromJobLog` does not read) and `crossRepoRedVerdict`, which judges the PR's failing files against the newest trunk verdict run's and answers `clear`, `cross-repo-red` or `cannot-ask`. A repository with no declared cross-repo leg (the primary) is `clear` with no `gh` call. Both arming doors call it after `blockerVerdict`: the refusal is a DONE, and it is said once on the pull request under `<!-- arm-refused: cross-repo-red <files> -->`, again when the file set changes. A leg or log that cannot be read is `cannot-ask`, never `clear`. The declared row is the exit: when it closes, a later head's leg is judged afresh.
