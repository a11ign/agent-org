The daily retro files a `safety-check-denied` ledger incident for every session-day whose transcript holds a denial by Claude Code's removal check (a11ign#4957 sixth class, agent-org#874), naming the command shape. A denial is a `tool_result` whose content STARTS with "Permission for this command was denied by a built-in Claude Code safety check, not by the user."; the same sentence quoted in an assistant message, a user message or the middle of a file read is not one. One incident per working-directory name, session id and UTC day, `ref: <cwd-dir>/<session id>@<YYYY-MM-DD> <shape>`, the shape (`nested-shell-c`, `node-e-rm`, `variable-target`, `other`) read from the first denial's `tool_use`; a denial whose `tool_use` cannot be found is `other`, never dropped. The pure leaf is `src/safety-check-denial-incident.ts`; `readSafetyCheckDenials` in `org-retro.ts` reads every Claude transcript touched in the 24-hour window and the retro prints one line (denials, session-days, first three refs). A transcript that cannot be parsed is counted apart as unreadable, never as clean, and a transcript root nobody could list reads `unknown`. It is not a trended number and not in `FAILURE_KINDS`. A removal a person approved leaves no denial in the transcript and is not seen.
