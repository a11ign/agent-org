Arming a pull request, guarding its merge and running the merge queue's dispatcher no longer call GitHub from core: `arm-pr`, `auto-arm-sweep`, `merge-guard` (with its lookups and the armed-race rule), `merge-queue` and `pr-armed-state` ask the code host's `rows` (contract 1.8), whose operations live in `plugins/github/rows/` (`armed-state`, `arming`, `sweep-reads`, `merge-guard-reads`). The decisions stay in core and call named operations (`readPullForArming`, `openBlockersOfRow`, `armMergeOf`, `readQueueSeat`, `requiredContextsOf`, `openPullsForQueue`, ...); `run` is optional on them, so a caller that has not moved still hands its own and one that has moved hands none. `CodeHost.armMerge` is real: it arms the merge, asks whether the pull request settled or was armed meanwhile when GitHub refuses, and reads it back. `runArmPr` and its helpers take a `run` of the form `(args) => stdout` (the leading command name is gone); `runMergeQueue` takes no `gh`; an unparseable list of open pull requests is now `could not ask GitHub for the queue` (exit 2) and not an uncaught throw. `ExecOptions.withoutEnv` takes variables off a plugin's program, so the merge queue's `gh` still runs without the git variables a hook sets. The fake code host's world models what arming and the guard read, `runArmPr` takes an optional `deliberate` verdict (default: the real one) so a test can stand in for the one verdict that reads GitHub's own JSON; and `docs/gh-call-baseline.json` goes down: seven files left it (the five callers, the armed-race rule and `host-drift-findings-and-notes.ts`, whose baseline entry was already stale) and two entries (`merge-guard/lookups.ts`, `ready-label-audit.ts`) are lower.
