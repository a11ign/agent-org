A pull request that touches `package.json`, `pnpm-lock.yaml`, `.npmrc` or `.github/workflows/` now dry-runs the release's version step in CI (agent-org#888; chairman, agent-org#885 class 3, a11ign/a11ign#4988). `ci.yml`'s new `release-dry-run` job, which `gate` waits for, clones the candidate tree and runs what `release-per-merge.yml`'s `version` job runs under the pnpm, `changeset` CLI and Node `release.yml` pins (`pnpm install --frozen-lockfile`, the repository's own `changeset version`, `pnpm install --lockfile-only`; `pnpm dlx @changesets/cli` where there is no lockfile), then runs the consumer's install of that tree (`npx pnpm@<pnpm-version> install --frozen-lockfile --ignore-scripts`, or npm's fresh resolution where there is no lockfile) as a11ign's `agent-org-newest-tag` does. It holds `contents: read`, keeps no credential and pushes nothing; a change that touches none of the four paths is a `success` with its steps not run. `src/packaging/release-dry-run.test.ts` runs the job's own scripts against fixtures: a lockfile that omits `@changesets/cli` fails the version step, and a lockfile that disagrees with `package.json` fails the consumer's.
