An Acceptance runs in the claimed worktree, and a leading `cd` into the primary checkout is run in the worktree instead (a11ign/agent-org#859, a11ign#4957 cause 2). `pr:open`'s check and CI's `acceptance-commands.ts` both called `execSync(command, ...)` with no `cwd`, so a command ran wherever `pr:open` was started and the rows' own `cd /home/agent/repos/agent-org && ...` read the PRIMARY checkout, which carries the change only after the merge. There is now one runner, `runAcceptanceCommand`: it runs each command with `cwd` at the top level of the worktree the process was started in, and a `cd` that OPENS the command (or its `bash -c '...'` string) into the primary checkout of that repository, or a directory in it, is run as `cd .` or `cd ./sub` and says so on the run's first line (`RUN-IN-WORKTREE: ...`), which keeps the fourteen open rows that carry the `cd` correct without amending their claimed bodies. A `cd` into another repository's checkout, a `cd` that is not leading, and a process that is no working tree are run as written. The file check that precedes a `tsx --test` line resolves a leading `cd`'s target the same way, so a test file only the worktree has is no longer reported missing. The refusal of such a `cd` at filing is agent-org#852's, unchanged.
