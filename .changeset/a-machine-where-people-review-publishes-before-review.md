A machine where people review can publish a run before its review: `tickets.providers.publish.when: "awaiting-review"` (`agent-org plugin config slack when=awaiting-review`). Since A11-179, Publish was offered only for a run Ready to merge, which needs every open pull request approved at its head. Where people review, the post is how a reviewer finds the pull request, so a `reviewed` run sat at "review: none yet" with no Publish. With `awaiting-review`, a run out of draft (`reviewed` or `ready-pr`) can be ticked once every open pull request was read at its head and waits on its review alone, with no required check red or running. A draft, a run not read yet and a published run cannot. The board's tick, the Run detail's Publish button, "publishing off" and `POST /api/publish` all ask one predicate (`publishable`), and `/api/queue` carries `publishWhen`. A published run reads Published and stays watched for feedback. `when` is a setting of the publisher concern, valid under any provider, `none` included, and kept on uninstall, like the reviewer's `required`. It is on the Plugins page's Publisher card and in doctor's publisher row. Absent, it is `ready-to-merge`, so no existing machine changes.
