The board, the org-health and retro readings, the DORA reader, the trace, the chairman's watch and answers and the tmp prune no longer call GitHub from core: `src/board-*.ts` (data, discussion, document, report, schedule-liveness, snapshot, snapshot-scope, summary-check, truth-audit), `src/org-health/sweep-readings.ts`, `src/org-retro/`, `src/dora.ts`, `src/trace/` (freshness, haiku-tier-report, headless-pilot, publish, trace), `src/messaging/` (github-writer, watch, watch-list, reply-cli, placeholders) and `src/prune-tmp.ts` ask the code host's `rows` (contract 1.11) for what they need, by name, implemented in `plugins/github/rows/` (`board-rows.ts`, `health-rows.ts`, `dora-rows.ts`, `trace-rows.ts`, `messaging-rows.ts`). A caller that runs `gh` itself asks the code host for a runner with its policy (`runnerWith`, `asyncRunnerWith`: a working directory, a bound, a buffer, a hook's git variables taken off, a `guard` that is core's rule, such as the leak guard or the chairman's read-only allowlist), so the process is the plugin's and the policy stays the caller's; `PluginDeps` gained `execAsync` and `ExecOptions` gained `cwd` and `input`. The board's GraphQL documents moved into the plugin. `docs/gh-call-baseline.json` goes down by 24 files. The fake code host's world gained `reports` (`board`, `health`, `dora`, `trace`, `messaging`, `snapshot`), and core's tests of these callers seed it instead of stubbing GitHub's answers.
