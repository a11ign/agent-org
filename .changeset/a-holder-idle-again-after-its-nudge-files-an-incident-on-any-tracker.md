A holder that was nudged and is idle again a full period after the nudge was delivered files a `claimed-worker-stalled` incident from the tick, on any declared tracker (a11ign/agent-org#860, a11ign#4957 cause 3). The only writer was a release carrying `nudgedAt`, and twelve agent-org holders sat idle for up to ten hours: a holder with an open pull request is never released (#2999), a `Claimed-nothing:` claim is never released (#3407) and a keyed row's release is withheld (#834), so each read `nudged` for good with no line in the ledger. `claim-stall.ts`'s `idleAgainReading` marks the `nudged` reading `idleAgain` when the holder's herdr status has been `idle`/`done` for one period (`idleLimitMs`, the same M or N the nudge used) counted from the later of its first idle tick after the nudge and the nudge's delivery, and `stalledNudgeEvents` writes the event with the ref a release uses (`<session>/#<row>/<nudgedAt>`), so a release later is the same line. The run's start is kept in `claim-stalls.json` (`idleSince` on a nudged entry) and dropped the tick the holder is not idle, so a holder that worked starts the period over. `IDLE_CLAIMANT_MINUTES` drops from 45 to 30, the chairman's bound for a holder with a pull request; the 10-minute figure for a stopped holder and the 60-minute `row-not-finishable` incident bound are unchanged.
