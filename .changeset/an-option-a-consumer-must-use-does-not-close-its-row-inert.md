A pull request that says a consumer's declaration must carry a value cannot close a row while it does not (agent-org#873, class `closed-on-merge-not-outcome`, a11ign/a11ign#4953). agent-org#782 added `routing.question`, wrote "not in this change" for a11ign's declaration in its acceptance file and closed a11ign/a11ign#4904 on merge; a11ign routed by `traits` for seven hours. The acceptance file now carries one structured line per option, `Consumer-declaration: <owner/repo>:<path> <key>=<value>` (`consumer-declaration.ts`, a leaf: it returns the declarations and the errors, and a malformed line is an error that names the line). `closes-mismatch-check.ts` has a fourth direction: for a pull request with such a line and a `Closes` that names a row, it reads each named file ONCE from the consumer's default branch and refuses while a key is not the value there, naming the file, the key, what it holds (or absent) and the two ways out (`Closes: none -- <reason>`, or land the consumer's declaration first); a file that cannot be read is a refusal naming that. The gh-call baseline of `closes-mismatch-check.ts` rises 2 -> 3 by `ceo` ruling (agent-org#838, option 1). CI wiring is agent-org#863; the detector for an option written with no such line, and the class's `guard`, are not set by this change.
