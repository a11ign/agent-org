A pull request in a declared repository whose name holds a character its key cannot (`a11ign/.github`, declared as the key `github`) is reviewed. The reviewer's seat is named for the declared key (`reviewer-github-6`), and its clone was looked up under that key alone, so a host that lists the clone as `clones[".github"]` (what `git clone` makes) was refused with "declares no absolute `clones.github` path" on every tick, and .github #6 sat unreviewed for more than twenty hours. `cloneOfKey` now asks `clones` for the key first, as it always did, then for the declared repository's name (`cloneOfDeclared` in `declared-clone.ts`); the name is no answer when another declared repository (the primary included) has it for its key or its own name, and the primary has no declared clone. The gate's verify stamps (`verifyCheckoutOf`) find the clone the same way. `agent-org doctor` checks every repository the project declares: a `clone of <owner>/<name>` row passes when the reviewer's label for its key reads back as that key and a clone is listed under the key or the name, and fails, naming the entry to add, when not. The `clones.github` alias added by hand can be removed.
