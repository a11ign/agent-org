A `hold:<session>` on a pull request no longer outlives its holder unseen (a11ign/a11ign#4970). The gate's tick reads each held pull request's holder: idle 30 minutes with no declared state, or no workspace carries its label, wakes it ONCE, naming the pull request and the hold and giving the three ways out (release it, declare the wait as a `worker:state` field, or re-take it `--until`). If the holder is still idle or gone 30 minutes after that, `orchestrator` (or `ceo`, when `orchestrator` is the holder) is ordered once to decide: release with the reason written on the pull request, or take the work over. No code removes a hold label; the orders only say how. A `blocked` declaration, a `waiting-ci`/`waiting-review` naming this pull request (`waiting-review` not once it is approved) and a working holder are left alone; `done` and a declaration older than the hold are not an excuse. A listing that is not the whole org is silence and the memory is kept. The new cause `hold-holder-idle` is declared (ACTION, `sonnet`/`medium`) and classified FINISH; its memory is `hold-holders.json` beside the stall memory. The daily #928 reading of approved-and-unqueued pull requests (item 4 of the row) is not part of this change.
