The org side can run an agent pull request's acceptance command, for same-repository agent branches only, and its verdict gates arming (a11ign/agent-org#1502, receiving side of a11ign#5460, ADR 0045 cut c). It runs on the HOST GATE, in a detached worktree of the pull request's merge ref, as an event on the project (plan a11ign#928 section 2). A pull request is eligible only when GitHub says it is not from a fork, its head repository is the base, its branch is `agent/*` and its author is an identity the host declares; every unreadable field is "not eligible", and an ineligible pull request has no checkout made and no command run. `orgSideAcceptanceEligibility`, `orgSideAcceptanceVerdict`, `checkoutPullRequestMerge` and `releasePullRequestCheckout` are in `src/acceptance-commands.ts`; `acceptanceGateOf` in `src/work-gate/pr-orders.ts` arms only a `pass` AT THE HEAD the pull request is now at, and the `pr-green-unarmed` order names the withheld ones and says not to arm them by hand. **OFF by default**: `A11IGN_PR_ACCEPTANCE_BY_GATE=on` in the tick's environment turns it on, runs at most two commands per tick, and remembers a verdict by head in `acceptance-verdicts.json` in the reviewer state directory. The `acceptance-commands` CLI that a project's workflow runs is unchanged.
