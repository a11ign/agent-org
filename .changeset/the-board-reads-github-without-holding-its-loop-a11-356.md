The board no longer holds its own loop while it reads GitHub (A11-356, code host contract 2.0). In ten minutes on 2026-10-27 the GitHub plugin's synchronous `gh` held the board thread 755 times for about a second each (`reviews.ts:18` alone 35 times a minute), so every card showed state minutes old, queue writes landed long after the call and the tracker's pooled sockets went stale. The code host's reads that the sweeps make on every pass (`readOwnLogin`, `readPullFeedback`, `readReviewState`, `readReplies`, `readPullState`, `openPullUrlsOf`, `readBranchCi`, `openDependencyPulls`, `readMergedFindings`) now answer a promise and run `gh` through `deps.execAsync`; the pool's sweeps (`watchFeedback`, `reviewNewHeads`, `startGreenReviewers`, `releaseReviewers`, `retargetStacked`) wait on them, a few reads at a time, and each sweep runs one at a time. The GitHub plugin reads a repository's open pull requests with one `gh pr list` that every pull request of it and every caller shares for ten seconds, where each caller read each pull request with its own `gh pr view`; doctor's stacking rows ask through `execAsync` too. `plugins/github/sync-gh-guard.test.ts` refuses a synchronous spawn under `plugins/`, requires those reads to reach `deps.execAsync` and never `deps.exec`, and names every operation that still runs `gh` synchronously (the writes and the reads done on an event), with why. A code host plugin of major 1 is refused; `peekReviewState` (optional) gives the reviewer plugin, whose start is synchronous, the state the sweep has just read. ADR 0015.
