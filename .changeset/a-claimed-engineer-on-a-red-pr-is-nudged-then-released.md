A claimed engineer idle on a red pull request is told to fix the red check within 10 minutes, and three unanswered nudges release the claim (a11ign/agent-org#743, a11ign#4437). Until now the nudge for such a holder was the generic "continue", a `waiting-ci` or `waiting-review` declaration excused it for as long as its pull request stayed open (red or not), and nothing counted nudges, so a holder with any open pull request read `nudged` for ever and kept its slot (agent-org#713 and #736 sat idle on red pull requests for hours). `redOwnPrs` reads the holder's own pull requests through `red-pr.ts`'s `brokenChecks` (the newest run of each name, a hold's own two jobs left out); under it the idle period is 10 minutes with or without a declaration, `waiting-ci` and `waiting-review` are voided, a young pull request has no grace, and a reviewer's pane, an approval or a check still running no longer excuse it, while a row's wait field and the pull request's own `awaiting-evidence` or `hold:` label still do. The nudge (`redCheckNudgePrompt`) names the failing checks and says to fix and push. A holder with a pull request open is now counted per stall (`nudges` in `claim-stalls.json`, absent for the first): a nudge is unanswered when its holder was idle for a full idle period after its delivery, the first and second are followed by the next nudge numbered `n of 3`, the third by the same `stalled` release the no-pull-request path performs (`ready` restored, no `answer:`), and the pull request is left as it is. A stall ends on a commit, a push, a pull request opened or a new claim after the latest nudge; a row comment or a changed file does not end it. The failure ledger still files one event per unanswered nudge (the superseding nudge carries it). A holder with no pull request is read exactly as before. The release comment `wake.ts` writes does not yet name the nudges; the order and the request carry `nudges` for it.
