An order whose class a project sets to `run` in `.agent-org/seats.json` is served by a one-shot decision run and falls back to its standing seat on any failure (a11ign/agent-org#904, Move 3 cutover seam of a11ign/a11ign#4505). `serveByRun` (`src/serve-by-run.ts`) looks the cause up in the registry, asks `seatModeOf`, leases the item, builds the brief, picks the tier through `decide` (Haiku unless the pick or a low-confidence answer says Sonnet), runs `runDecision` and applies with `applyDecision`; a refused, failed, timed-out, stale or leased order is prompted to its seat exactly as before. The run happens in the tick before `deliver` (which is synchronous) and `deliver`'s per-order loop asks the new `serve` option for the answer already in hand. A served wake is appended to `served-by-run` beside the wake ledger and `settleWakeOutcomes` writes it to the trace with `servedBy: "run"` and the run id; a seat's settled wake carries `servedBy: "seat"`. No class ships with this row and the option is absent by default, so behaviour is unchanged until a project names a class `run`; deleting the file, or setting the cause to `seat`, is the one-line revert.
