Starting a reviewer no longer holds the board's loop (A11-379). A start held it about nine times, about 10 s in all, because the reviewer port's `herdr`, `git`, install, token mint and claim calls were synchronous spawns on the board's thread. Reviewer contract 2.0: `start`, `live`, `settled`, `close`, `retire`, `listedPulls`, `repostVerdict`, `reprompt` and `unblock` answer a promise (`verdictFileOf` reads files only and stays synchronous). Code host contract 3.0: `readReviewClaims` and `writeReviewClaim` answer a promise, run through `deps.execAsync`, and the claim protocol (`claimHead`) awaits them. The atomic reviewer makes no synchronous spawn: `herdr` runs through an async runner, the checkout, install, token mint, verdict door and Codex trust lookup through `execAsync`. The port stays in the board's process, so the claims it has seen from other instances are kept. A start, a close or a retire in flight holds its seat: a second call for it is refused (or answers busy, for a close) until the first settles, and the git work against one clone is done one call after another. A reviewer plugin of major 1 and a code host of major 2 are refused.
