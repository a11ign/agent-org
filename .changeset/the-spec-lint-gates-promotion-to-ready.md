Promotion to Ready asks the spec lint, and Jev's spec review has its decision use (a11ign/agent-org#1017, a11ign/a11ign#5117). Behind `rows.specLint` in `.agent-org/project.json`, absent meaning OFF, so a project that never declared it promotes exactly as before. With it on, `row-file --promote=<n>` refuses a row whose fenced `spec` block fails the lint, naming the field (`tests.cases[0].then`) and the rule, and refuses a build row (a Region that names a source file, and a `Tests-first:` or `spec` marker in the body) that carries no block. A Region prefix with no checkout on the host is unchecked, never a refusal, and a file is looked for on `origin/main`, not the working tree. Each refused finding is one failure-ledger line, `spec-lint-refused<TAB><ts ms><TAB>#<row> <field> <rule>`. `DECISION_USES` gains `spec-review`: after a promotion that passed the lint, Jev reads the spec, and a score under 3 leaves the row Ready, adds `spec:review` and `answer:product-manager` after a comment that asks, and never blocks; no provider, the use off or a provider that is down adds nothing. Not in this release: the retro's line for the refusals (a11ign/agent-org#1056) and the flag in a11ign's own declaration.
