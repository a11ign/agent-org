An Acceptance that loads TypeScript through `tsx` is refused at filing and at `pr:open` (a11ign/agent-org#870). `tsx` is not a dependency of this tool (a11ign#4389) and Node strips types itself, so `node --import tsx --test x.test.ts` dies on `ERR_MODULE_NOT_FOUND: Cannot find package 'tsx'` on every host and in CI (PR #844 got no verdict); `no-loader.test.ts` reads units and package scripts and never an Acceptance, so nothing refused the spelling at the door and 37 shipped `.acceptance/` files carry it. `tsxAcceptanceReason(body, tool)` refuses a command that names `--import tsx`, `--import=tsx`, `--loader tsx`, `pnpm exec tsx` or a `tsx <file>` runner, names the line, and gives the way out (`node --test <file>`). It is called by `acceptancePathsReason` (so `row-file` and `row-file --promote=`) and by the `acceptance` report CI and `pr:open` share, before the command is run. The one-shot registry runner is not refused (it fetches `tsx` rather than failing to resolve it, and it is the placeholder Acceptance of many test fixtures). A bare `tsx` counts only at a command's own position, so `git grep tsx` and a path such as `src/tsx-fixtures/a.test.ts` are not refused; prose outside the Acceptance is not read; a body that declares `Hand-run:` keeps that meaning. A body with none of the spellings reads exactly as before.
