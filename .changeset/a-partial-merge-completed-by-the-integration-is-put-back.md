A partial plan step's merge no longer ends its ticket when the tracker's own integration completes it (A11-178). The tracker contract is 1.5: an optional `undoAutomaticCompletion(key, comment)` moves a ticket the integration completed back to the state it left and posts the comment, and leaves a person's completion alone (the Linear plugin reads the ticket's state history for who moved it); an optional `closingWords` of `Keywords` lists every word the tracker completes a ticket by anywhere in a body. When a finished run's `Partial:` pull requests merged (or it is a later step whose own pull request has not), and the tracker reads the ticket Completed, the board puts it back with a comment naming the merged pull requests, the step and what remains, and queues the next step in the same sweep; a later step is put back as its run starts. A run it could not put back reads Needs you with why, and the board asks again on every sweep. The `closes` report (`pr:open`, and CI's `acceptance` job) now reads the closing words anywhere in a body, and refuses a partial body with one next to its own ticket's key and any body with one next to another ticket's key, which is what completed A11-127 on agent-org#1827; the worker's brief says so.
