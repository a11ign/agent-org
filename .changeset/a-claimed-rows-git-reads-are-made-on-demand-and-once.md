The claim-stall pass no longer runs git for facts a row's reading never asks for. A held row's newest own commit and push were read (`git rev-parse` and `git log`, for the branch and for `origin/<branch>`) while its facts were built, so a row owned by an open pull request, a merged one or a blocker paid four subprocesses for nothing; they are now read when the reading asks, and each of a row's four git facts (commit, push, worktree changes, work at risk) is read at most once per tick. A git that will not answer for a commit now holds the row by name (`is HELD, not released`) instead of skipping it as `not evaluated`; it is still neither nudged nor released. agent-org#1083.
