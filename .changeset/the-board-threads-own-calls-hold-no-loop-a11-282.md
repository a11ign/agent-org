The board thread no longer holds its own loop for the calls its tick and sweeps make to herdr, GitHub and a child process, which delayed every write (Queue, Stop, Approve…) and `GET /api/session-asks`, and which the board's reliability figure "synchronous holds an hour" counts. The `gh` wrapper's start-up check runs in a child process the instance waits for without holding its loop; the tick lists herdr's workspaces and agents (`readAgentsAsync`) through the asynchronous herdr the starts already used; the clone sweep lists the organisation through the code host's new `repositories.readRepositoriesAsync`; and the sweep of the stacked pull requests' bases asks its new `sweepRetargetsAsync`, five `gh` reads for each pull request, which had held the loop a second at a time. Code host contract 2.2 adds those two operations, OPTIONAL: a code host without them is read through the synchronous ones, as before, and the GitHub plugin gives both. `/api/health`'s `blocking` list now names the code that asked for a herdr call and not `herdr-agents.ts`. `scripts/loop-load.ts` is repaired: it reached the real Linear with its placeholder key, since the tracker's transport (`freshFetch`, A11-359) never went through the offline `fetch` the script preloaded, and so timed the internet, 300 ms a tracker read, against its 200 ms bound; its network is now refused from the machine itself at once, and what holds the board thread there is the one synchronous call a quiet tick still makes (`systemctl --user show`, which reads herdr's start).
