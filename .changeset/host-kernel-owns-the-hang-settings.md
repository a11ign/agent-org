`src/host-kernel.ts` now holds the text of `/etc/sysctl.d/90-a11ign-hang.conf` (`HANG_CONF`), with `kernel.softlockup_panic = 0` and `panic_on_rcu_stall`, `panic_on_oops` and `panic` kept, and each line carries its reason. The header records why the file exists (a11ign/a11ign#3846: a 2 h 15 min unnoticed hang) and why the soft-lockup line changes (A11-279: on 2026-10-25 a 26 s soft lockup that would have cleared became a reboot that killed every run). `node src/host-kernel.ts --hang-conf` prints the text, and `host:check` now raises a finding when the file or a live `/proc/sys/kernel` value differs (`HANG SETTINGS DIFFER`), when kdump is not loaded (`KDUMP NOT LOADED`), and when this user cannot read the newest crash record in `/var/lib/systemd/pstore` (`CRASH RECORDS NOT READABLE`), each with the exact command the chairman runs as root; a refused read is `NOT READ`. These are manual-fix findings (`host:install` cannot clear them, so the host-drift gate does not wake a session for them every tick) and are left out on a host with no user systemd. `--hang-conf` beside another flag is refused. Nothing in the module writes under `/etc`, so no check can put `softlockup_panic = 1` back. A11-279.
