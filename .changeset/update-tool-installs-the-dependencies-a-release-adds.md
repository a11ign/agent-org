`update-tool` installs the `dependencies` a release adds BEFORE it moves the host's agent-org checkout. It used to install nothing, so a release that adds a runtime dependency (agent-org#522 makes `@a11ign/toolchain` a `dependency` at `^0.7.0` and imports it from 163 files, while the host's checkout holds 0.1.2 with no `lib/`) moved the checkout onto a `node_modules` that lacked it and every program of the tick, the gate and the launcher failed on its first import: the tick crash of 2026-10-09 (a11ign/a11ign#4392) again, with the one session that mends it asleep. The move now reads the `dependencies` of `package.json` at the release tag, compares them with what `node_modules` holds (an exact version, `^`, `~` or `*` is judged by version; any other range by absence, or by having changed from the checkout's own), and when they differ installs them with `pnpm install --prod --no-frozen-lockfile --ignore-scripts --ignore-workspace` in a fresh worktree beside the checkout, so the live `node_modules` is never half-written under a running tick and no clean install deletes it. Only after that succeeds is the finished `node_modules` renamed into the checkout and the checkout advanced; the long-running units are restarted for it. A failing install HOLDS the move (the checkout and `node_modules` stay where they were, the half-made tree is removed) and `host:check` reports `host-install-pending` on `package.json` naming the command and what is missing. The check runs on every run, so a checkout an older mover already advanced onto a release it lacks the dependencies of is mended by the next one. A release whose `dependencies` are unchanged advances with no install, as before. a11ign/agent-org#714.
