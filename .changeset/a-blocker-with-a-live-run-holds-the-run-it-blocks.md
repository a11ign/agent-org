A blocker with a live run holds the run it blocks, whatever its pull requests so far did (A11-206). On 2026-10-24 the board let A11-204 go because every pull request A11-183 had so far was merged, while A11-183's run was still running and its main pull request was not open yet. A blocker now holds while its ticket has a run that is queued, starting, running (planning, working, in a review round or waiting on a question) or parked on a question; a Talk session is judged by the finished run it resumes. A blocker whose merged pull request declared a `Partial:` line holds until a pull request with the closing keyword merges or the ticket is Done, and a blocker whose merged pull requests are not read yet holds until the next tracker sweep reads their bodies (`blockersDeclared` on the queued run, written by `learnFromBlockers` from the same `readMergedFindings` read). A11-154's rule stays: no live run and every pull request merged and read as complete lets the blocker go even with its ticket In Progress, and a code host that reads no bodies falls back to it. The card names the reason, such as "Waits for A11-183 (running)", "Waits for A11-183 (step 1 of 2 merged)" or "Waits for A11-183 (its merged pull requests are not read yet)".
