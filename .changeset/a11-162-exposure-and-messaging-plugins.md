The exposure and messaging are now **agent-org plugins**. `local` (the concern's default: the board listens on loopback and serves nothing) and `tailscale` (the board's page and the worker terminal served on the tailnet with `tailscale serve`, never Funnel) are the bundled exposure plugins `plugins/local` and `plugins/tailscale`, behind the exposure contract (now 1.1), and `telegram` is the bundled messaging plugin `plugins/telegram`, behind the messaging contract (now 1.1). Core asks the activated exposure for the board's name, the `Host` and `Origin` values it answers to, the terminal's address and the serve calls, in `ticket:serve`, `ticket:ui`, `ticket:pair`, `agent-org start` and `stop`, and for the event receiver's Funnel path (`src/event-tunnel.ts`) and the trace pages' address (the kernel notes); the `tailscale` command is run in `plugins/tailscale` and nowhere else (`src/plugins/boundary.test.ts` refuses it, a tailnet host name and `api.telegram.org` anywhere in core). The tailnet doctor rows moved into the Tailscale plugin with their names and words, and so did onboard's Tailscale warning (now three steps: installed, operator, ports). The loopback exposure adds the rows `local ports` and `local terminal`; the messaging plugin adds the rows `telegram token file` and `telegram chat`, which are what `messaging:check` checks.

**Switching exposure is `agent-org plugin enable local` plus a restart.** `enable <name>` of a plugin the concern's block does not name now switches the block to it when the block names another plugin of that concern: it keeps each setting both plugins declare (`port`, `uiPort`, `terminal`), drops the rest (`tailnetPorts`) and a `terminal` that is the outgoing plugin's own tailnet address, and says which. The plugin it leaves is RELEASED first (a plugin's optional `release`), while it is still the enabled one and after the readers have accepted the change: Tailscale removes the two `tailscale serve` entries it holds for this board, and no other, and a release that cannot (Tailscale is not running) refuses the change by name and writes nothing. `disable`, `uninstall` and `install --replace` release the same way. The line that says what must restart now names the instance, the page and the terminal. The Tailscale plugin's `tailnetPorts` entries now name the right services (the page and the terminal).

**Messaging is written by `agent-org plugin`.** `install`, `enable`, `disable`, `uninstall` and `config` of `telegram` change the primary project's `project.json` `messaging` key through the Settings page's path, which keeps its place (A11-157 Decision 7); the key takes `enabled` (absent is true; `false` reads as off and keeps every setting). `reply-cli`, `watch`, `listen`, `route-guard` and `decision-confidence-post` build the provider through the registry; `messaging:pair` stays the core's command and calls the plugin's `pair`; the listener's offset file is the core's (`src/messaging/offsets.ts`). The `messaging:pair` package script now runs `src/messaging/pair.ts`. A provider the registry does not hold is refused by name; the old `KNOWN_PROVIDERS` list is read from the catalog. `agent-org start` and `agent-org stop` are asynchronous inside and unchanged outside. No host file changes meaning: a host with no exposure block, or with `tickets.serve`/`servePorts`, resolves to the bundled plugins as before.
