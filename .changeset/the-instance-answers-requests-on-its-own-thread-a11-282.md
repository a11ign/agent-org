Every board page answers while the instance is busy. The instance's HTTP server now runs on a thread of its own, the request thread, and every read (`/api/config`, `/api/tickets`, `/api/queue`, `/api/plugins` and the rest) is answered there from the latest snapshot of the queue and the pool, which the board thread posts after every change and every second. The board thread still runs the pool, the tick and the sweeps, and is still the queue's one writer: a write (Queue, Stop, Approve…) is forwarded to it whole and answered by the routes it always had, so a write can still wait while a sweep's `gh` runs. With a 2 s `gh` holding the sweeps, a read's p99 fell from 1.95 s to under 100 ms. `GET /api/health` now answers both threads' loops (`loop.requests`, `loop.board`), `boardSnapshotAgeMs`, how old the board thread's last snapshot is, and `requestThreadSyncCalls`, the synchronous spawns on the request thread since it listened, each also logged as an ERROR. `GET /api/session-asks` stays on the board thread, since it writes the After-merge checks file. A request thread that exits is started again, up to 3 times a minute; a 4th exit stops the instance, and its service restarts it. A11-282.
