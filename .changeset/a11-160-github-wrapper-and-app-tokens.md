The `gh` routing wrapper every agent runs through (`host/gh`), its renderer and the rules about writing it, the App-token minter and the authoring switch's script are now the GitHub plugin's (`plugins/github`), behind an optional `wrapper` group of the code host contract (version 1.3). Core's `host:install`, `host:check`, the tick's re-render and the instance's start-up check ask the activated code host for the wrapper's text, its install target and its refusals (a wrapper that names no App never replaces one that does, A11-84), and still write the file; a code host with no `wrapper` installs none. The wrapper is the template it was byte for byte, but its minter and authoring-switch script now live in `plugins/github`, so an installed wrapper reads `DIVERGED` until the instance restarts (its start-up re-renders it) or `agent-org host:install` runs. Doctor's `gh wrapper` and `app token <role>` rows moved into the plugin's section with their words, a `wrapper roles` row compares the roles the installed wrapper routes to an App with the roles `host.json` declares, and the App-token rows now run on a ticket-only host too. Onboard's step that copies the reviewer App's key into `<AGENT_ORG_HOME>/apps/` is the plugin's, and a step that throws refuses onboard by its sentence. A plugin is given `place`: where the host file says the machine keeps what a wrapper is rendered from. `docs/gh-call-baseline.json` loses `host/gh`; nothing rises.
