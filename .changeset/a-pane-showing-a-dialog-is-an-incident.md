A pane that shows a menu or dialog waiting for a choice is an incident on the next tick, raised to the seat that owns the session (a11ign/agent-org#463, epic a11ign/a11ign#4437, class `tool-drift-interactive-prompt`). The tick now reads every live session's pane (the read it already makes for stalls, `herdr --session org agent read <label> --source recent --lines 40`) in a `paneDialogs` phase after the tear-downs, and `src/pane-dialog.ts` says whether the text ends in a live menu: at least two options numbered 1..n or a selector-marked list, with a selector or a key hint (`Press enter to confirm`, `esc to go back`) and a question above it. An idle prompt, a numbered list in ordinary output, a code block, a working pane (`esc to interrupt` is not a hint) and a dialog already scrolled past are not dialogs. The first tick that sees one orders the owner (`reviewer-<n>` and `worker-<n>` to the `product-manager`, a standing seat to itself) with the question, the choices and the pane, once per dialog text and again only when the text changes. The order's first line is `Class: tool-drift-interactive-prompt`, so the failure ledger records it under that kind and a second dialog is a counted repeat. An order that was not accepted is not remembered and is tried again next tick. The memory is `pane-dialog-raised.json` in the host's state directory.
