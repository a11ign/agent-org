`closes-mismatch-check` refuses a pull request that is a claimed row's own deliverable and declares a `none` Closes (a11ign/a11ign#4770, chairman 2026-10-10: one deliverable per row). Of the 29 pull requests merged since 2026-10-08 that declared `none`, five left their row open after the merge, and neither existing direction saw it: a `none` that closes nothing agrees with what GitHub resolved. The third direction compares the PR's head ref with the `Claimed-branch:` of every open claimed row's claim record (read by `claimRecordOf`, so a released claim holds nothing) and names the row and the instruction: declare the row in the Closes line and file what remains as its own row. A fork's branch, and a branch no row claimed (a dependency bump, a docs-only change), pass with `none`. A head or a row list that cannot be read, or a row whose claim record lies beyond the 100 newest comments read, is SKIPPED with the reason printed, never passed as clean, and the check's other two directions still run. Nothing is asked unless the declaration is `none`, so a PR with a Closes line costs no extra call. It runs in the existing `mergeSafety` step, with no new job.
