A release now ships the board UI's build, and `install.sh` and `agent-org update` fetch it (A11-191, part of A11-187). `release.yml` gains two jobs after the release: `ui-build` finds the tag the push released, builds `ui/` at it and packs `agent-org-ui-<tag>.tar.gz` and its `.sha256`, and `ui-attach` adds both to the GitHub Release. A release that ships a build says so with `"agentOrg": { "shipsUiBuild": true }` in its `package.json` (this one and every later one). For such a release `install.sh` (a new step, `Downloaded its UI build`, and `curl` and `gzip` in its preflight) and `agent-org update` download the two files, check the tarball against the checksum, and unpack it into `versions/<tag>/ui-build/` before `current` moves, where `ticket:ui` serves it at `/next`. A checksum that does not match, or a release whose build CI has not attached yet, fails the install or refuses the move and leaves `current` where it was; the next `agent-org update` tries again. A release before the marker installs as it always did, with no download. When `update` finds nothing newer it gives the folder `current` names its build if its release ships one and the folder has none, so the first release that ships a build gets it on the host that installed it with an older `update`. `agent-org doctor` gains a `ui build` row that warns when the running version's release ships a build and none is found. `AGENT_ORG_RELEASES_URL` points both at another place to download releases from.
