CI's `closes` report (`ciClosesReport`, in `CI_BODY_REPORTS`) also passes a ticket-mode pull request's declaration: `Closes A11-127`, or `Refs A11-127` with a `Partial:` line. It read the first as MALFORMED and the second as MISSING, and ticket-mode `pr:open` refuses `Closes: none`, so no ticket-mode body could pass both (a11ign/a11ign#5713 failed `acceptance` this way). It reads a ticket with `pr:open`'s own grammar, now in the leaf `src/ticket-mode/ticket-references.ts` (`referencesIn`, `ticketClosesReport`), with the tracker's default words and any ticket-shaped name as the first word of a `Closes` or `Refs` line, and says which form it found. A closing line that names a row (`#N`), `none` or prose first is left to the row report, so a row that was tried and got wrong is not read past. `Closes #N`, `Closes owner/repo#N` and `Closes: none — <reason>` read exactly as before, and `extractClosesDeclaration`, which the readers of GitHub rows branch on, is unchanged. The cross-repo refusal's exit now names a ticket: a `Cross-repo-red: A11-123` line (a ticket key, read by its shape with no tracker read) clears it, and `#n` or `owner/repo#n` no longer does, since the GitHub rows it named are closed (`declaredRows` and `stateOfRow` are gone; `declaredTickets` replaces them). A pull request that newly reds the leg is still not armed without the line. A11-127.
