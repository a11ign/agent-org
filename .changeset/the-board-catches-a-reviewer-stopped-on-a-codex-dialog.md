The board catches a reviewer stopped on a Codex dialog (A11-221, step 2). The reviewer contract is now 1.6 and gains the optional `ReviewerPort.unblock`, which the pool calls for a started head with no posted review. The atomic reviewer reads the pane only when herdr lists the seat's agent `blocked`. If the dialog is Codex's "Trust this folder?" for a repository root that is one of `host.json`'s `clones`, it trusts the root in Codex's config and answers with `enter` (at most twice per seat and head); a trust dialog for any other root, a root it cannot read, an entry a person set to `untrusted`, and every other dialog get no key and are reported as stuck. A stuck reviewer shows `the reviewer stopped on a dialog it cannot answer: "<first line>"` on the pull request's review line, and the run that holds the pull request is handed to a person as Needs you with the same first line until a look finds no dialog. The reviewer's workspace is left open for a person to answer in herdr. A reviewer of contract 1.5 reports no dialog.
