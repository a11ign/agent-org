The GitHub plugin reads each repository's open pull requests once per sweep, in one GraphQL query that every reader shares, and `/api/health` serves how many calls it makes (A11-365). Before, `reviews.ts` ran 35 `gh pr view` a minute and `open-pulls.ts` 12 `gh pr list` a minute on 2026-10-27, a call for each pull request for each reader, each holding the board's thread for about a second. Now the reviewer's state, the board's feedback, the replies, the open list, the dependency bot's pull requests, and a merged pull request's findings all read one snapshot per repository, kept for 30 seconds, dropped by every write the plugin makes to the repository; a pull request that is not open is read by its number once and remembered. A repository that cannot be read is not asked again for 10 seconds and its pull requests are never read one by one instead. Which checks a base requires now comes from the base's rulesets and branch protection in the same query. The asynchronous REST reads that repeat (the runs of a branch and their jobs, a merged pull request's diff) are sent with their ETag, so a 304 costs the rate limit nothing. Every `gh` the plugin starts is counted by kind, per minute and per sweep, logged, and served as `githubCalls` on `/api/health`. The code host contract is 2.1: `readCallCounts` and `refreshPull`, both optional; a caller that writes down what it read to compare it later (the head and description a stand-off round is given, the heads a Decisions round is given, the heads and files a run ends with, a round's replies) reads afresh first. A test holds `plugins/github/` to no pull request read outside the snapshot but the four operations the contract keeps synchronous (A11-356); row mode's `rows/` is held to a ratchet.
