## What it is

Since A11-149 a reviewer starts only after the instance claims the head with a commit status (`agent-org/review`). The claim is written as the `reviewer` App and read as the `scheduler` App, and on the agents host every claim failed: first for a missing "Commit statuses" permission, then because the read-back was answered from the `gh` wrapper's per-account read cache (a write by another account does not drop it), so the claim was released on every sweep. Doctor, the board and the log said little, and a lone instance had no way to review at all. This change checks the permission in doctor, says the failure on the board, retries the head, lets a lone instance review without a claim, and reads the claim past the cache.

## Change

- `src/ticket-port/review-claim.ts`: `claimHead` answers `unclaimed` with the `step` that failed (`read`, `write`, `readback`) and GitHub's own reason (the first line `gh` printed on stderr), and `alone` when the write was refused after a clean read and no other instance was seen within the lease; `claimEntriesOf` reads with `-H "Cache-Control: no-cache"`, which the wrapper never caches; `othersSeenIn` finds the other instances among a head's entries.
- `plugins/atomic-reviewer/port.ts`, `src/ticket-mode/reviewer-port.ts`, `pool-context.ts`, `server.ts`, `review-command.ts`: every claim listing records the other instances seen (kept in `reviewers.json` as `seen`, none past the lease); `alone` starts the reviewer with no claim and no release, after the head is read again; `start` answers `unclaimed` (reviewer contract 1.2), and why a reviewer has no claim is kept in `reviewers.json` as `unclaimed`, for a pool start and a `ticket:review` start alike.
- `src/ticket-mode/pool-reviewers.ts`, `board-view/pull-review-state.ts`, `pool.ts`, `server.ts`, `ui.html`: the pull request's line (`cannot claim for review: <reason>`, `reviewing without a claim: <reason>`), one board warning (`claimWarning`) and one log line per reason.
- `plugins/github/app-token.ts`, `wrapper.ts`, `identity-checks.ts`, `src/plugins/policy.ts`, `manifest.ts`, `src/install/doctor.ts`: doctor rows `commit statuses reviewer` (write) and `commit statuses scheduler` (read), a dry read of each App's installation permissions run as the minter's `permissions` mode.
- `src/install/interim-guards.ts`, `doctor.ts`: `onboard` retires `gh-read-cache-off.conf` once the installed `gh` wrapper is the declared one, and `doctor` fails while it stands.

## How it is proven

Each acceptance line of the ticket is proven by a named test:

- doctor checks each identity for the commit status permission and names the one to grant: `A11-172: the reviewer App's installation without Commit statuses write fails ...`, `A11-172: the scheduler App, which only lists the claim, needs Commit statuses read ...`, `A11-172: each identity passes with the write permission ...`, `A11-172: the permission is read from the installation and never tried ...`, `A11-172: a machine that starts no reviewer has no claim ...`, `A11-172: a role that is a user account is asked for its access ...` (`plugins/github/identity-checks.test.ts`), `A11-172: the installation's permissions are read with the App's JWT ...` (`plugins/github/app-token.test.ts`), `A11-172: doctor hands the code host the review claim's identities ...` (`src/install/doctor.test.ts`);
- a claim that fails is not recorded as started, is tried again, and `ticket:review` starts it once the claim succeeds: `A11-172: a claim GitHub refuses is not recorded as started ...`, `A11-172: ticket:review starts a head the pool could not claim, once the claim succeeds ...` (`plugins/atomic-reviewer/two-pools.test.ts`);
- a failing claim shows on the pull request's line and once as a board warning: `A11-172: a pull request whose claim cannot be written reads ...`, `A11-172: one board warning covers every pull request ...` (`src/ticket-mode/board-view.test.ts`), `A11-172: a head that cannot be claimed shows on its pull request's line ...`, `A11-172: the claim problem is said once in the log ...` (`two-pools.test.ts`), `A11-172: a start the claim refused is shown on each pull request's line and once as the board's warning ...` (`src/ticket-mode/pool.test.ts`), `A11-172: the board warning for review claims GitHub refuses is drawn once ...` (`src/ticket-mode/ui.test.ts`);
- a lone instance starts anyway and says so, a second instance stops it: `A11-172: a refused write after a clean read is alone ...`, `A11-172: another instance seen just within the lease ...`, `A11-172: another instance's live claim on this head is held ...`, `A11-172: a read that failed is never alone ...`, `A11-172: a re-review whose claim cannot be written is alone ...` (`src/ticket-port/review-claim.test.ts`), `A11-172: a lone instance whose claim cannot be written starts the reviewer anyway ...`, `A11-172: with a second instance present the reviewer does not start without a claim ...`, `A11-172: an instance seen before a restart is still seen after it ...`, `A11-172: a reviewer started without a claim is still said to be, after a restart ...`, `A11-172: a head ticket:review started without a claim is said so on the board ...`, `A11-172: a sighting of another instance older than the lease is neither adopted ...`, `A11-172: ticket:review says so when it starts a lone instance's reviewer without a claim` (`two-pools.test.ts`), `A11-172: a claim another instance wrote while this one's write was refused ...` (`review-claim.test.ts`), `A11-172: the instances seen and the starts made without a claim are kept on disk ...` (`src/ticket-mode/reviewer-port.test.ts`);
- the claim's read bypasses the read cache and sees a write by another identity: `A11-172: the claim's read asks past the gh wrapper's read cache ...` (`review-claim.test.ts`), `A11-172: a claim read straight after a write by another identity sees the write ...` and its positive control (`src/packaging/review-claim-read-cache.test.ts`, the real wrapper over a stub `gh`);
- the hand-set drop-in is retired and doctor fails while it stands: `A11-172: the read-cache drop-in is removed ...`, `A11-172: the read-cache drop-in is kept ...`, `A11-172: the read-cache drop-in is retired beside the other guards ...` (`src/install/interim-guards.test.ts`), `A11-172: the gh-read-cache-off.conf row fails while the drop-in stands ...` (`src/install/doctor.test.ts`).
