A blocked head whose pull request body changed is re-reviewed whatever state the holding run is in (A11-274, step 2 of 4). `rereviewFor` (`src/ticket-mode/pool-reviewers.ts`) used to wait for the run to be `finished`, and counted a body change only when the run's `finishedAt` came after the block. A run that stopped without an outcome gets no worker round for a block, so its `finishedAt` never moved, and a body fix was never looked at (a11ign.github.io#3). Now `mayRereview` (`src/ticket-mode/queue/queue-rereview.ts`) waits only while the worker is working. It admits a finished run in any outcome, and a running one on a dialog (`waiting`) or idle on a `working` note while it has a round left. A running run with none waits for its end and is handed back then, since a run's end drops a hand-back. `bodyAnswersBlock` keeps A11-235's `finishedAt` rule only for a run the block gives a worker round to: one that is watched (`isWatched`), or a round queued since the block, which is that round under way. For every other run, each line changed since the head's last look counts. `countRereview` and `handBackRereview` act on the same runs, so each re-review is still one of the run's rounds, and a run at `MAX_FEEDBACK_ROUNDS` is handed back once with no reviewer started.

A parked run that stopped without an outcome is released once every pull request it holds has merged and their bodies are read (`isReleasable`, `src/ticket-mode/board-view/blocker-cleared.ts`), as A11-258 releases a `needs-human` one. Its next step is then queued, or its ticket completed. Neither its card nor the release's log line (`src/ticket-mode/pool-blocker-cleared.ts`) says "the blocker cleared": it asked nothing.
