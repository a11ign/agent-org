herdr has a service of its own: the instance and the terminal `Want=` and start after `agent-org-herdr.service`, nothing `Requires=`, `BindsTo=` or `PartOf=` it, and an update never restarts it, so restarting the instance or the ui leaves every worker's pane and agent running. `agent-org start herdr --move` moves a server that runs outside the unit and retires the `KillMode` drop-in and the gh-wrapper watchdog; `doctor`'s `herdr scope` passes for a server in the unit. An update builds `tool/versions/<tag>`, points `tool/current` at it, restarts the instance and the ui, and leaves live runs on the version folder they started on (`doctor` lists each run's version, and the Board shows a run's version only when it differs from the instance's). A release whose changeset starts `Breaking:` drains with runs live: no new run starts, the Board shows the banner, and after `tickets.updateMaxDeferHours` the live runs are stopped and re-queued onto the new version. The conventions plugin's refresh runs at every update and leaves a live run's copy alone.
