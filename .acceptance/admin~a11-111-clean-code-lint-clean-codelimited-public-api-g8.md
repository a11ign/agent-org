## What it is

`clean-code/limited-public-api` (G8) flags a module that exports more than 50 members. The rule is on at `error`. Each of the twenty flagged modules is now under the limit: the module is split into files in dependency order, each with at most 48 exports, and every importer in the repository is rewritten to the file that declares each name. Nothing is waived.

## Change

- `eslint.config.ts`: `"clean-code/limited-public-api": "error"`, with its reason beside it.
- The thirteen modules split into a directory of their own (`src/<module>/`): `acceptance-commands`, `claim-stall`, `host-units`, `org-health`, `org-retro`, `row-file`, `ticket-mode/board-view`, `ticket-mode/queue`, `wake`, `work-gate/pr-orders`, `work-gate/reads`, `work-gate/tick`, and the `work-gate` barrel, whose 362 re-exports are removed in favour of direct imports. Seven modules that were already under the limit once unused exports were removed keep that change.
- Production code keeps its behaviour: each moved path is rebased where it is computed from `import.meta.url` or a relative string, and the two places that load a module by path (`node-strips-types.ts`, the start-up program in `ticket-mode/server.ts`) now name the file that declares what they read.
- The browser board page is served as `board-view.ts` joined to the files it was split into, so the page's functions are all there.
- Tests that pin a file's text, its population, or a path-keyed table now read the module's files together (`src/lib/module-source.ts`), or name the file that declares the value. No assertion was weakened; see the PR body for each exemption or count that changed.
