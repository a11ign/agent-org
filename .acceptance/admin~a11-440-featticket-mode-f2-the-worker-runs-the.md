The review of a worker's local diff before its pull request opens (A11-440, step 1 of 2), behind `tickets.localReview`, which is off by default. When the pool starts a run that opens pull requests on a machine with it on, it writes the `local-review-on` mark beside the outcome file and adds step 5b to the brief (`localReviewStep`): run `ticket:review-local` after the last commit, fix each blocking finding, run it again. `ticket:review-local` (`src/ticket-mode/local-review.ts`) refuses a tree with uncommitted tracked changes or an empty diff, writes `git diff <base>...HEAD` beside the outcome file (the base by `pr:open`'s rule: `--base`, else `origin/HEAD`, else `origin/main`, read through an asynchronous `git`), asks the M2 eval's reviewer (`codex exec`, read-only, the `row-review` skill) with the ticket as the spec, and records the commit and verdict for that worktree in `local-review.json`. `pr:open create` on a marked run (`pr-open-ticket.ts`, `local-review-record.ts`) refuses a create with no review of the tree, a review of an earlier commit, or a review against another base than the create's diff, and one not convinced whatever the body says; one with no verdict (the reviewer could not run) passes only when the body has a `## Local review` section. A record of another shape is read as no review. The board's own review of each new head is unchanged. The hook refuses a worker that writes the mark or the record.
