When a ticket run's worker is out of Claude allowance, the board holds every new start until the reset, and resumes the parked runs after it without a person (A11-434, step 2 of 2). The first run held records the reset on the queue (`Queue.allowance`, kept in the queue file). `nextStarts` starts no run but a talk session until 2 minutes after that reset (`ALLOWANCE_GRACE_MS`), and `writerToStart` holds after-merge check runs for the same time. A held run that answers again drops the hold on starts (`releaseStarts`). `whyNothingStarts` gives the reason. Once a held run's reset has passed, `resumeAfterReset` (`src/ticket-mode/allowance.ts`) cancels the limit menu with Esc when the pane shows it, and sends the run a carry-on prompt. It sends the prompt again at most once every 15 minutes, and never to a talk session or to a run that stopped while its pane was being read. A board restart's resume prompt skips runs held on the allowance (`pool-resume.ts`). Step 1's detection, and the Waiting: allowance card, are unchanged.
