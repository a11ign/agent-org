The outside arming pass (`outsideArmPass`, `src/auto-arm-sweep.ts`) no longer reports "armed" from `arm-pr`'s exit code alone. `arm-pr` exits DONE both when it arms and when it deliberately refuses, so the pass read a refusal as an arm: a11ign/a11ign#1595 was ejected from the merge queue, logged "armed", and its GraphQL read said `autoMergeRequest: null`. Now, after an exit of 0, the pass reads the pull request back (`armedQueryArgs`, `armedFromApi`, `armedReason` from `src/pr-armed-state.ts`). Armed on the read-back: `result.armed`, logged `OUTSIDE-ARM: #n armed -- read back: <reason>`. Not armed, with the `arm-pr: NOT arming #n -- ...` line captured from `arm-pr`: `result.left` with that line as the reason, logged `OUTSIDE-ARM: #n NOT ARMED -- <line>`, which never says "armed". Not armed and no refusal line: `failed`. A read-back that throws, or fails to parse: `failed`. A nonzero exit: `failed` with `COULD NOT ARM`. `runArmPr`'s exit codes are unchanged, and `src/arm-pr.ts` is not edited.
